## Где что лежит — одно место на одну вещь

| Что | Где | Размер |
| --- | --- | --- |
| Где мы сейчас и роадмап | `Docs/STATUS.md` | ≤ 1 экран: кто чем занят, открытые PR, роадмап. История — `Docs/Archive/` |
| Решения владельца | `Docs/DECISIONS.md` | одна строка на решение |
| Флаги | `Docs/FLAGS.md` | одна строка на флаг |
| Что делаем в фиче | `Docs/specs/` | спека |
| Ревью и обсуждение кода | комментарий в PR | вердикт + замечания |
| Очередь между агентами | `MAILBOX/TO_CODEX.md`, `TO_CLAUDE.md` (ветка research) | запись ≤ 10 строк, новое сверху |
| Вики | Status-and-Roadmap | короткий пересказ STATUS для людей, без своих деталей |

`CLAUDE_STATE.md` больше не ведётся — его роль у `STATUS.md`.

## Три дорожки

| Дорожка | Что это | Нужно для мержа |
| --- | --- | --- |
| **Баг** | чинит сломанное, без флага, до ~80 строк кода | тест-репро + зелёный CI + Codex OK. Отдельного серверного окна на PR нет — баг проверяется окном пакета |
| **Фича** | новое поведение, флаг `wb_bot_*` OFF | спека с таблицей ситуаций → код + unit/caller → CI + Codex OK. Серверная пара D-046 — только если её требует спека |
| **Доки** | спеки, статус, решения, бэклог | Claude мержит сам. Новая большая спека (новая система) — критика DeepSeek и «ок» владельца до кода; правка пункта существующей спеки и бэклог — без критика |

Мерж: Codex OK на точном SHA + зелёный CI → мержит тот, кто писал, сразу (D-039). Синк dev в PR — только перед мержем.
Лимит: 4 открытых PR с кодом (D-050), доки не считаются.

## Окно и плейтест

- **Серверное окно 600 с — одно на пакет**, перед плейтестом, не на каждый PR. Ворота — D-061 (стоят ≤ 20 % в каждой команде; US на суше к 4 мин ≥ 6/7; 0 ботов в круге 10 м > 60 с; p95 `PATHTIME` по итогу окна ≤ 2,5 мс).
- FAIL ворот — пакет не выдаётся; причина становится багом или строкой спеки.
- Новая находка плейтеста, которую окно пропустило, — первым делом новая метрика в воротах, потом фикс.
- Во время плейтеста владельца в ветки пакета ничего не пушить.

## Записи

- Почта: ≤ 10 строк, без копий логов. Формат: `PR/SHA · вердикт · что нужно от адресата · ссылка на детали` (PR-комментарий или `E:/WarsBots/QA/...`).
- Ревью Codex — комментарием в PR; в почту — одна строка со ссылкой.
- Отчёт после плейтеста — раздел в `STATUS.md`; длинный разбор — в `Docs/Research/Reports/`, в статусе ссылка.
