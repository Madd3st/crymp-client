# WarsBots: цикл разработки

Действует с 01.11.2026. Заменяет прежний поток «фича → билд → плейтест → следующая фича».
Цель: ситуации, в которых бот тупит, продумываются **до** кода и проверяются **сценариями**, а не только руками владельца.

## Цикл одной фичи

```
1. SPEC      →  2. SCENARIOS  →  3. CODE   →  4. REVIEW  →  5. MERGE   →  6. FLAG
(1 страница)    (каталог)        (1 агент)    (Codex)       (в тот же     (принято →
                                                             день)        default ON)
                         ↘ ночной батч сценариев ↙
                    7. ПЛЕЙТЕСТ ВЛАДЕЛЬЦА — раз в веху, не после каждой фичи
```

### 1. Спека (`Docs/specs/NNN-имя.md`, шаблон `templates/SPEC.md`)
- Одна страница. Пишет Claude, критикует Gemini или DeepSeek (ищут ситуации, где бот затупит).
- Обязательна **таблица ситуаций**: что происходит → что бот должен сделать → как это проверить.
- Без спеки код не пишется. Исключение: багфикс меньше 20 строк с понятным репро.

### 2. Сценарии
- Каждая строка таблицы ситуаций становится сценарием: карта, стартовая позиция, условие, метрика, порог PASS.
- Сценарии живут в каталоге `Docs/scenarios/<карта>.md` и запускаются существующим probe/triage-харнессом (`summary.json`).
- Сценарий пишется **до** кода и сначала должен падать (RED) на текущей ветке.

### 3. Код
- Один агент на задачу (по умолчанию Claude Code). Параллельно в одной области никто не пишет.
- Тест — по возможности обычный C++ unit на модуль (`Tests/Bot*Tests.cpp`).
  Python-«caller»-тесты, которые вырезают методы из исходника по тексту, — только когда без этого никак, не больше ~150 строк.
- Коммит помечается агентом: трейлер `Agent: claude|codex|gemini|deepseek`.

### 4. Ревью
- Codex: `/codex:review` на PR. Ревью проверяет спеку и сценарии, а не только дифф.

### 5. Мерж
- Интеграционная ветка: `warsbots/dev`. Все PR идут в неё.
- **Не больше 2 открытых PR с кодом одновременно** (D-043, D-047); PR только со спеками и документами не считаются. Стек глубже 2 запрещён.
- Агент мержит сам, когда выполнены оба условия (D-039):
  - CI полностью зелёный на точном SHA головы PR. Если после CI был push, нужен новый CI;
  - ревью Codex — OK, без P1.
  - для PR, меняющего поведение ботов: серверный прогон «до/после» на CI-сборке точного SHA, пороги спеки выполнены (D-046).
- Если ревью Codex нет или оно не OK, мержит владелец, либо агент по явному «мержи».
- Мерж в тот же день, когда выполнены условия.
- Флаги и defaults меняются только по решению владельца, независимо от того, кто мержит.

### 6. Флаги
- Новая фича под флагом `wb_bot_*`, default OFF — это нормально.
- После приёмки по сценариям владелец решает: default ON. Флаг удаляется в течение недели.
- **Не больше 5 экспериментальных флагов одновременно.** Шестой — только после закрытия одного.
- Лаунчер плейтеста не включает флагов, которых нет в списке «принятых/в приёмке» (`Docs/FLAGS.md`).

### 7. Плейтест владельца
- Раз в веху (несколько фич), на сборке `warsbots/dev`, по чек-листу из спек.
- Найденная проблема становится строкой в таблице ситуаций и сценарием, а не сразу кодом.

## Отчёты

Один формат, `templates/REPORT.md`, не больше 10 строк. Никаких квитанций JSON в `Docs/Coordination/` для человека.
Сырые логи и метрики — в `build/` или на E:, в отчёте только ссылка.

## Протокол общения агентов

- **Почты между агентами нет.** Никаких MAILBOX, TO_CLAUDE, TO_CODEX, wake-квитанций.
- Общение только через три места: **спека** (что делаем), **PR** (обсуждение и ревью — комментариями в PR), **`Docs/STATUS.md`** (где мы сейчас).
- **`Docs/DECISIONS.md`** — одна строка на решение: `ID | дата | решение | почему | кто решил`. Только решения владельца и принятые/отклонённые предложения.
- Ревью не хранятся файлами в репе. Смержили PR — ревью осталось в истории GitHub.
- Сырые логи, метрики, демо — на E: или в `build/`, в репе только ссылка из отчёта.
- Раз в веху: `Docs/reports/` старше вехи переносятся в архивный тег, в рабочей ветке остаются только отчёты текущей вехи.

## Роли

| Агент | Делает | Не делает |
| --- | --- | --- |
| Claude Code | спеки, код, сценарии | ревью своего же кода |
| Codex | ревью PR, рискованные правки по запросу | параллельный код в той же области |
| Gemini | анализ видео/плейтестов, критика спек | код в ветках `dev` без задачи |
| DeepSeek | исследования, критика спек | код без адресной задачи |
| Владелец | решения (defaults, мерж), плейтест вехи | читать квитанции |

## Что сохраняется из старых правил
Все инварианты из `AGENTS.md` (никаких SetPos/импульсов ради зелёного теста, игру локально не собирать,
defaults меняет только владелец, не удалять `build/` целиком) остаются в силе.
