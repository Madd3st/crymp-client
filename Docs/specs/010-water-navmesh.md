# SPEC-010: вода в навмеше — каждый водный объём уровня запекается слоем плавания

Статус: draft (на критику DeepSeek, затем «ок» владельца)     Автор: Claude     Критик: DeepSeek
Флаг: `wb_bot_water_links` (default OFF) — новые связи воды в маске путей. Новый навмеш — только данные бейка, живые Navmesh не подменяем без «ок» владельца.
Основание: плейтест 11.11, владелец: «каждый водный объём из level.editor_xml запекается плавательным слоем (своя высота поверхности, связи в открытую воду/на сушу), без ручной разметки (D-041). Бассейн подлодки Shore — первый кейс».

## Что должно измениться
Сейчас в навмеше одна вода — плоскость моря на высоте из командной строки (`--water 99.5`). Вся вода ниже или под крышей выпадает:
- бассейн внутри подлодки Shore;
- проход под корпусом.

Бот, упавший в бассейн, вне навмеша. Каждые 2 с он пишет `NAV fallback start_off_mesh` (251 из 282 в окне 38e63072). Выбраться ему помогает только исполнитель нырка #41, который в плейтесте 09.11 ушёл на 21 м глубже цели.

После спеки бейкер сам берёт из данных уровня каждый водный объём с его высотой поверхности и кладёт его в навмеш водой. Он сам находит связи «вода ↔ суша» и «закрытая вода → открытая вода» (нырок). Тогда путь из бассейна на берег — обычный путь Detour, а командир видит, что средняя палуба связана с берегом не только лестницей.

Вывод: бассейн — **отдельный водный объём со своей поверхностью** 89,37. Сейчас его нет в навмеше по двум причинам:
- бейкер знает только одну плоскость;
- правило «твёрдое над клеткой — воды нет» срезает всё под палубой.

Данных уровня хватает, ручная разметка не нужна.

## Что делаем

**1. Список воды из уровня (`Tools/RecastBake/level_water.py`, без движка).**
- Читаем `<map>.cry` → `level.editor_xml`; префабы раскрываются из `GameData.pak` → `Prefabs/*.xml` с позицией и поворотом экземпляра.
- Из сцены берём:
  - `WaterVolume` (замкнутый многоугольник, поверхность — z точек + `Pos`, `VolumeDepth`);
  - `River` (полоса шириной `Width` по сплайну; поверхность по z узлов);
  - океан из `leveldata.xml` → `WaterLevel`.
- Выход: `<map>.water.json` — список поверхностей с id объекта уровня (имя + GUID). Его хэш попадает в `manifest`.
- `--water Z` из командной строки больше не нужен: океан берётся из уровня. Для старого бейка ключ остаётся и даёт тот же результат.

**2. Водный слой в бейке (`recast_bake.cpp --water-volumes <map>.water.json`).**
- Для каждой поверхности кладутся водные квады области 4 (`kWaterArea`) на её высоте и только внутри её многоугольника.
- Правило «твёрдое над водой»:
  - для океана — как сейчас (DS-062/067);
  - для объёма — квад блокирует только твёрдое **в пределах высоты агента над поверхностью** (1,8 м): палуба над бассейном на 93,4 не мешает, плита на 90 — мешает.
- Береговая линия — та же консервативная логика, что у океана (подъём ≤ шага в клетке).
- Если в бассейне на Shore 0 квадов, бейк падает с ошибкой, а не отдаёт тихо меш без бассейна.

**3. Связи без разметки (генерируются бейкером, пишутся в `links.txt` с новыми видами).**
- **`SwimExit` (вода → суша):**
  - от края водного полигона до ближайшего полигона суши, если подъём ≤ предела выхода из воды (физика — вопрос 1);
  - обратная связь `SwimEnter` (суша → вода) — прыжок/спуск в воду, если перепад ≤ безопасного.
  - Для бассейна: пол отсека 90,16 над водой 89,37 (+0,8 м) — по одной связи на каждый край, где пол рядом.
- **`Dive` (закрытая вода → открытая):**
  - 3D-заливка водного пространства по геометрии OBJ (клетка 0,5 м, ниже поверхности объёма, выше дна, вне твёрдого) от объёма до столба воды с открытым небом;
  - нашлась — связь `Dive` с ломаной (точки через найденный проход), длина под водой ≤ предела кислорода (вопрос 2); не нашлась — связи нет, лог бейка `water <id> no_dive`.
  - Портал `Portal925` — только подсказка для проверки, не источник: решает геометрия.
- Все связи помечены видом в `links.txt`; рантайм берёт их только при `wb_bot_water_links 1` (маска путей, как у прыжков).

**4. Рантайм.**
- Бот в бассейне стоит на водном полигоне → обычный путь, без `start_off_mesh`.
- Исполнитель `Dive` — исполнитель #41, переделанный под ломаную связи:
  - штатное плавание, курс на следующую точку;
  - снижение — штатный `ACTION_CROUCH` (`SetWarsBotSwimDown`), пока следующая точка ниже;
  - всплытие, когда точка выше или над головой открытое небо;
  - успех — физически дошёл до конца связи и стоит на водном полигоне снаружи; таймер успехом не считается;
  - неудача → `NoteLinkFailure`/бан как у прыжков; лестница остаётся запасным путём.
- Лог: `WATER link start/done/failed kind= link= bot=`.

## Что из #41 заменяется, что остаётся

| #41 сейчас | После SPEC-010 |

## Риски
- **Ошибка в раскрытии префабов** (поворот/масштаб) даёт воду не там. Защита: сверка с ямой из логов (x 2117–2123, y 1882–1885, вода 88,4–89) в тесте.
- **Неверная связь `Dive`** уводит бота в тупик под водой. Защита: флаг, бан связи со второго сбоя, запасной режим.
- **Новый навмеш меняет пути всех ботов Shore.** Защита: сравнение путей старого и нового меша вне бокса воды, D-042, серверная пара.
- **Без `.cry` карта водных объёмов не получает.** Тогда старый бейк и запасной режим.
