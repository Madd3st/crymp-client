# SPEC-005: задача бота и командир команды (Power Struggle)

Статус: draft     Автор: Claude     Критики: DeepSeek, Gemini (не назначены)
Флаг: `wb_bot_ps_squads` (default OFF до приёмки), работает поверх `wb_ps_capture`. В `trial` с SPEC-004 будет 5 флагов: шестой нельзя, пока один не закрыт. Как освободить место, решает владелец (вопрос 4).
Перенесено из черновика SPEC-002 «цели команды» (ветка `claude/spec-002-ps-goals`, 62d5f4c1), нумерация — решение 04.11. Код — после SPEC-007 (очередь владельца 06.11).

## Что должно измениться
Сейчас каждый бот сам берёт ближайшую чужую точку. Вся команда стартует рядом, поэтому выбирает одну цель и идёт одним маршрутом в одну пробку. Бункеры в целях не участвуют вообще.

После изменения у команды есть «командир»: не бот, а общая логика сервера. Он раз в несколько секунд раздаёт ботам задачи — взять точку, взять бункер, держать точку — поровну и по навыкам. Бот выполняет свою задачу и возвращается к ней после боя.

Цель вехи M1 (D-040): каждая команда на Shore берёт не меньше 2 бункеров.

## Решения владельца, которые уже есть (02.11)
- Делить поровну, и по навыку тоже: в каждой группе примерно одинаковый состав навыков.
- Защита захваченной точки зависит от числа ботов и необязательна: при малой команде её может не быть.
- Бункеры берём: это точки возрождения.

## Что делаем
1. **Бункеры в списке целей.** Добавить захватываемые `SpawnGroup` (`bCapturable` в `Properties`, как читает HUD: `HUDRadar.cpp:2030`) с зоной из той же привязки AreaShape (DS-072). Как именно захватывается бункер, проверяет вопрос 1 до кода.
2. **Командир — один на команду, внутри `BotManager`, чистая логика в `BotTeamOrders.h` (без движка, unit-тесты).**
   - **Вход:** список целей с владельцем и типом, живые боты команды с позицией, навыком и текущей задачей.
   - **Выход:** задача на бота: `{цель, роль: capture|hold}`.
   - **Пересчёт:** раз в 5 с и сразу при событии — точка взята или потеряна, бот возродился.
   - **Деление:** число групп = min(свободные цели, ⌈ботов/3⌉). Группы равны по числу (разница ≤ 1) и по сумме навыков (разница ≤ 1). Цели групп — разные. Порядок целей: бункеры и энергия раньше заводов. Расстояние — по длине пути навмеша от базы, а не по прямой.
   - **Стабильность:** задача у бота не меняется чаще раза в 20 с. Исключения: цель взята, бот возродился, группа погибла.
   - **Защита:** если ботов в команде ≥ 2 × число свободных целей, на взятую точку остаётся 1 бот. Иначе защитников нет.
3. **Бот выполняет задачу.** `UpdatePSCapture` берёт цель из задачи командира вместо `BotPSCapture::Update`. Бой важнее задачи; после боя бот возвращается к ней.
4. **Держать точку из укрытия.** Внутри зоны захвата бот выбирает место, откуда не видно входа врага. Укрытия из `Shore.spots.txt` (запечь, как для Steelmill — вопрос 3) или локальная проверка лучами у точки. Смотрит на подход, а не на центр.
5. **Лог.** `PS ORDER team= bot= target= role= group= reason=` при каждой смене задачи. Метрики считаются по нему.

Все сценарии: PS Shore, CI-пара EXE точного SHA, 15 ботов, флаги профиля Shore-15 плюс `wb_bot_ps_squads 1` и `wb_bot_unstick 1`. 3 повтора, если не указано другое. RED — текущее поведение на `warsbots/dev`.

## Не цель
- Вождение техники и лодки: SPEC-006.
- Застревания на пути: SPEC-004.
- Покупка оружия, связь с игроком, голосовые команды.
- Командир-бот с картой и приказами для людей.

## Затрагиваемые модули
- `BotPSCapture.cpp/.h`: бункеры в снимке целей, тип цели.
- Новый `BotTeamOrders.h` (чистая логика) и `Tests/BotTeamOrdersTests.cpp`.
- `BotManager`: командир на команду, пересчёт, события.
- `BotBrain.cpp`: `UpdatePSCapture` берёт задачу; удержание из укрытия.
- Данные: `Shore.spots.txt` (запечь, живые данные не подменять).
- Player, GameRules, CMake и сеть не трогаем. События захвата читаются тем же путём, что `wb_ps_events`.

## Открытые вопросы до кода
1. **Как захватывается бункер на Shore:** класс, `bCapturable`, зона AreaShape, время захвата. Проверить по XML уровня и Lua PS. Строка 3 (M1) зависит от этого.
2. **Длина пути от базы до целей:** считать при загрузке уровня по навмешу или брать прямую с поправкой. Нужен замер цены.
3. **Укрытия у точек:** запечь `tactical_spots` для Shore (бейкер на dev, PR #19) или считать лучами на месте.
4. **Лимит `trial`:** с SPEC-004 занято 5 мест. Какой флаг закрыть до кода, решает владелец.
