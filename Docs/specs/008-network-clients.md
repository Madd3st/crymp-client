# SPEC-008: боты видны правильно любому клиенту CryMP

Статус: draft, только спека, без кода; критика DeepSeek 07.11 внесена     Автор: Claude     Дальше: Codex (сеть), «ок» владельца
Флаг будущего кода: `wb_net_input` (default OFF, D-050). Инварианты AGENTS: никаких fake INetChannel / `OnClientConnect(0)`, глобальных правок `IsPlayer`/channel, обходов античита; штатная сериализация CryMP и optional groups; один интегратор Player/GameRules/сети.

## Что видел владелец (LAN 07.11, Codex `3e9aa031`)
| Прогон | Результат |
| --- | --- |
| Неизменённый CryMP v26, `wb_net_ext 0` | Заходит; боты — манекены: нет анимации и поворота, едут задом, в таблице игроков нет |
| `wb_net_ext -1` (авто) | Клиент падает: `Malformed packet`, затем `Entity 0 for RMI CGameRules::ClTextMessage not found` |
| Кик `Server probe hash mismatch` | Античит CryMP на `game/scripts/warsbots/powerstruggle.lua`; в тесте снят `sv_cheatProtection 0`. Это не решение для чужих серверов |

## Причина манекена (код, факты)
- Анимацию, поворот и направление движения удалённого игрока клиент берёт из **`INPUT_ASPECT`** (`IPlayerInput.h:58`, `eEA_GameClientDynamic`): `SSerializedPlayerInput` — `stance, deltaMovement, lookDirection, bodyDirection, sprint, lean` (`Player.cpp:5386-5404`, `Serialize_CryMP` при `mp_crymp 1`, иначе `Serialize_Default`).
- На сервере это состояние даёт `m_pPlayerInput->GetState()`. Объект ввода создаётся **только при канале** (`Player.cpp:985-999`: `CNetPlayerInput`, если `GetChannelId()`). У бота канала нет → `m_pPlayerInput` пуст → в аспект уходит `SSerializedPlayerInput()` по умолчанию: нулевое движение, направление по умолчанию. Позицию клиент получает из физики, поэтому бот «едет», но анимация стоит, а корпус смотрит не туда.
- Наш клиент WarsBots это обходит своим путём `WarsBotMotion` (optional group, только при `WarsBotsWire()`); ванильный клиент этой группы не знает.

## Причина отсутствия в таблице игроков (код)
`HUDScore.cpp:251`: строки строятся по `IActor::IsPlayer()`; наш клиент добавляет `IsMatchParticipant` под `WARSBOTS_EXPERIMENTAL_SPAWNER`. На ванильном клиенте `IsPlayer()` у бота ложно (нет канала). Сделать его истинным без канала нельзя по инвариантам (fake channel / глобальный `IsPlayer`). **Вывод:** строка в таблице у неизменённого клиента в рамках инвариантов недостижима; возможна только у клиента, который сообщил о поддержке расширения (вариант B).

## Предусловие кода — античит (критика DeepSeek 07.11)

До первой строки кода (только чтение и офлайн, без игры): что именно хэширует probe CryMP (`Server probe hash mismatch` на `game/scripts/warsbots/powerstruggle.lua`) — файлы клиента, серверный набор скриптов или их пересечение — и **пройдёт ли неизменённый клиент при штатной защите** (`sv_cheatProtection 1`) на сервере с WarsBots. Если не пройдёт, решаем это до A (перенос/упаковка скриптов сервера, не обход). Без ответа SPEC-008 в код не идёт: A без входа на сервер бесполезен.

## Что делаем

### A. `INPUT_ASPECT` за актёра без канала (единственный вариант этой спеки)
Сервер, только для своих ботов (`m_warsBotActor`, ownership guard), под `wb_net_input`:
- **Писать `SSerializedPlayerInput` в точке сериализации `INPUT_ASPECT`** (`CPlayer::NetSerialize`, ветка аспекта ввода), не подменяя `m_pPlayerInput`: никакого нового объекта ввода, `CPlayerMovement` и вся логика, читающая `m_pPlayerInput`, видят то же, что сейчас (`nullptr`).
- Поля: `deltaMovement` — направление движения в осях корпуса (из `SetWarsBotMotion`: direction/speed), `lookDirection` — прицел, `bodyDirection` — направление корпуса, `stance`, `sprint`, `lean` = 0. Сериализация — **штатная** (`Serialize_Default`/`Serialize_CryMP` по `mp_crymp`), формат пакета не меняется: неизменённый клиент читает бота как обычного игрока.
- `ChangedNetworkState(INPUT_ASPECT)` — только при изменении больше порога (направление 5°, скорость 0,5 м/с, смена stance/sprint), не чаще 10 Гц на бота.
- **Бюджет трафика:** 15 ботов, ≤ 10 Гц, размер аспекта как у игрока → прирост исходящего трафика сервера ≤ 15 × 10 × размер `SSerializedPlayerInput`; замер — `net_stats`/логи канала на прогоне Shore-15 ON против OFF; PASS — прирост не больше, чем дали бы 15 игроков-людей с тем же движением.

### B. Рукопожатие WarsBots-клиента — отдельная спека (SPEC-008b)
Включение optional group `WarsBotMotion` только для канала, который сообщил поддержку (по образцу `mp_crymp`), и отказ от `wb_net_ext -1` «по LAN-адресу» (`BotNetCompat.h:51-56`) — отдельная спека после A. Строка в таблице игроков — только там.

### C. `ClTextMessage` с Entity 0 — отдельный баг, не под флагом
Клиент падает на `Entity 0 for RMI CGameRules::ClTextMessage` при `wb_net_ext -1`. Это ошибка порядка/адресата RMI, она чинится отдельным PR без флага: адресный лог отправки в `GameRules.cpp::SendTextMessage` (вызывающий, канал, текст), порядок bind GameRules у подключающегося клиента, исправление. Не маскировать.
