# SPEC-008: боты видны правильно любому клиенту CryMP

Статус: draft, только спека, без кода     Автор: Claude     Критика: DeepSeek (D-051), Codex (сеть), затем «ок» владельца
Флаг будущего кода: `wb_net_input` (default OFF, D-050). Инварианты AGENTS: никаких fake INetChannel / `OnClientConnect(0)`, глобальных правок `IsPlayer`/channel, обходов античита; штатная сериализация CryMP и optional groups; один интегратор Player/GameRules/сети.

## Что видел владелец (LAN 07.11, Codex `3e9aa031`)
| Прогон | Результат |
| --- | --- |
| Неизменённый CryMP v26, `wb_net_ext 0` | Заходит; боты — манекены: нет анимации и поворота, едут задом, в таблице игроков нет |
| `wb_net_ext -1` (авто) | Клиент падает: `Malformed packet`, затем `Entity 0 for RMI CGameRules::ClTextMessage not found` |
| Кик `Server probe hash mismatch` | Античит CryMP на `game/scripts/warsbots/powerstruggle.lua`; в тесте снят `sv_cheatProtection 0`. Это не решение для чужих серверов |

## Причина манекена (код, факты)
- Анимацию, поворот и направление движения удалённого игрока клиент берёт из **`INPUT_ASPECT`** (`IPlayerInput.h:58`, `eEA_GameClientDynamic`): `SSerializedPlayerInput` — `stance, deltaMovement, lookDirection, bodyDirection, sprint, lean` (`Player.cpp:5386-5404`, `Serialize_CryMP` при `mp_crymp 1`, иначе `Serialize_Default`).
- На сервере это состояние даёт `m_pPlayerInput->GetState()`. Объект ввода создаётся **только при канале** (`Player.cpp:985-999`: `CNetPlayerInput`, если `GetChannelId()`). У бота канала нет → `m_pPlayerInput` пуст → в аспект уходит `SSerializedPlayerInput()` по умолчанию: нулевое движение, направление по умолчанию. Позицию клиент получает из физики, поэтому бот «едет», но анимация стоит, а корпус смотрит не туда.
- Наш клиент WarsBots это обходит своим путём `WarsBotMotion` (optional group, только при `WarsBotsWire()`); ванильный клиент этой группы не знает.

## Причина отсутствия в таблице игроков (код)
`HUDScore.cpp:251`: строки строятся по `IActor::IsPlayer()`; наш клиент добавляет `IsMatchParticipant` под `WARSBOTS_EXPERIMENTAL_SPAWNER`. На ванильном клиенте `IsPlayer()` у бота ложно (нет канала). Сделать его истинным без канала нельзя по инвариантам (fake channel / глобальный `IsPlayer`). **Вывод:** строка в таблице у неизменённого клиента в рамках инвариантов недостижима; возможна только у клиента, который сообщил о поддержке расширения (вариант B).

## Варианты

### A. Стандартный `INPUT_ASPECT` за актёра без канала (основной)
Сервер, только для своих ботов (`m_warsBotActor`, ownership guard): объект ввода бота `CBotPlayerInput : IPlayerInput`, создаётся на сервере при `IsWarsBotActor()` без канала. `GetState()` отдаёт то, что бот реально делает этим кадром: `deltaMovement` — локальное направление движения (из `SetWarsBotMotion`: direction/speed в осях корпуса), `lookDirection` — прицел, `bodyDirection` — направление корпуса, `stance`, `sprint`. Сериализация — **штатная** (`Serialize_Default`/`Serialize_CryMP`), формат пакета не меняется, поэтому неизменённый клиент читает его как обычного игрока.
- Плюсы: работает с любым клиентом v26; не трогает канал/античит; ничего нового в протоколе.
- Риски: `ChangedNetworkState(INPUT_ASPECT)` на каждом изменении — нагрузка на сеть (15 ботов); `CPlayerMovement` на сервере не должен начать читать этот ввод как управление (бот движется своим путём) — ввод только для сериализации, `Update()` пустой; проверить, что `Serialize_CryMP` (mp_crymp 1) не ждёт клиентских полей.

### B. Рукопожатие по образцу `mp_crymp` (дополнительный)
Клиент CryMP с поддержкой WarsBots сообщает её штатным путём (как `mp_crymp`), сервер включает optional group `WarsBotMotion`/`warsBotActor` **только для этого канала**. Неизменённый клиент без рукопожатия получает только вариант A. `wb_net_ext -1` больше не включает расширения «по LAN-адресу» (`BotNetCompat.h:51-56`: сейчас `isServer || IsPrivateAddress` → сервер всегда шлёт расширения → `Malformed packet` у ванильного клиента).
- Строка в таблице игроков и прочие улучшения — только для клиентов с рукопожатием.

### C. `ClTextMessage` при входе
Отдельно: выяснить отправителя RMI `ClTextMessage` с Entity 0 — адресный лог отправки в `GameRules.cpp::SendTextMessage` (вызывающий, канал, текст) и порядок bind GameRules у подключающегося клиента. Ошибку не маскировать.

## Ситуации и приёмка
Неизменённый CryMP v26 (SHA256 `0d953581…ad9e0`), LAN, Steelmill IA 4 бота и Shore PS 15, сервер — CI-пара точного SHA, `sv_cheatProtection` штатный (1) для итоговой приёмки.
