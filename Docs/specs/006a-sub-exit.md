## Первым делом (владелец 07.11, отчёт Codex 70e629b3): почему навмеш не ведёт с подлодки в воду

Codex: у подлодки бот 91 с в радиусе 2,5 м в воде, NAV fallback 26 → 361 за первые 719 с (1170 за матч). Разбор того же лога:

| Где бот | Яма с водой **внутри корпуса**, x 2117–2123, y 1882–1885, вода z ≈ 88,4–89, бот оседает до 87,6. Пол отсека — 89,5–90,1 |
| Падения | 9 за матч (320, 451, 547, 692, 1020, 1336, 1540, 1692, 1740 с), **выходов — 0**: кто упал, остаётся до смерти/конца |
| Почему нет пути | Бейк Shore: `--zmin99.5 --retain-box2103,1877,90,2138,1892,99.5 --water99.5` (`Shore.manifest.json`). Всё ниже 99,5 м отрезано, кроме бокса отсека **от z 90**. Связей в `Shore.links.txt` две: прыжок с силой на рубку и лестница (2116,1;1880,6;90,25)→(2117,5;1880,6;99,77) |
| Что ведёт в яму | Перед падением: 2 раза — точка отхода SPEC-004 у края ямы с `tier=2` (прямой проход не подтверждён: `backoff to=(2119.5,1881.5,89.7)`, `(2122.9,1881.9,90.1)`), 6 раз — перепланировка `UNSTICK spread` (путь в обход союзника идёт по краю ямы), 1 — ступень спринта |
| Наружная вода | С палубы в море путь есть (whole-route PASS 30.10, `--water99.5`); проблема не в выходе в море, а во внутренней яме |

**Вывод:** «навмеш не ведёт в воду» — это внутренняя яма отсека, вырезанная бейком (нижняя граница бокса 90 м). Попасть в неё можно (край не защищён), выбраться — нет. Варианты:

1. **Не падать (код, без правки навмеша):** точки отхода/ожидания SPEC-004 и обход союзников не берут кандидатов с `tier=2` у края меша с перепадом > 1 м вниз (проверка проекцией: под точкой нет полигона в пределах 1 м по высоте); путь по краю ямы — с наценкой стоимости у границы меша в боксе отсека.
2. **Выбираться (нужно решение владельца, D-041/D-048):** перепечь Shore с нижней границей бокса 87 м, чтобы яма стала водой меша, плюс связь выхода из ямы — если в геометрии есть физический выход (лестница/уступ ≤ 0,5 м). Без такого выхода яма — тупик, и правильно только п. 1.
3. **Ограничить повторы (SPEC-004b):** fallback каждые 2 с в яме (976 строк) не помогает — отдельное правило в SPEC-004b.

Вопрос владельцу: разрешить перепечь Shore с боксом от 87 м (D-048), если Codex подтвердит физический выход из ямы? До ответа — только п. 1 и 3.

## Причина по логу 07.11 (факты)

| Время | Что | Строки лога |
| --- | --- | --- |
| 0,06 с | Первая волна: 4 бота США появляются внутри корпуса (z 90,6), 3 — на палубе (z 100–103) | `created ... position=` |
| 4,86–16,60 с | Лестницу (низ (2116,1;1880,6;90,2), верх (2117,5;1880,6;99,8)) проходит **один** бот 65471 | `LADDER start` / `LADDER done` — единственные за матч |
| 12–17 с | Трое остальных ждут в очереди у основания. Двое ближайших стоят вне 2-метровых ворот лестницы, поэтому для них это не «ожидание у лестницы» (`ApplyLadderExecutor` их не глушит), а стоянка с остатком 11–12 м | `UNSTICK step=sprint ... corner=(2116.5,1879.7,90.2) remaining=11.8 stuckFor=4.1 allies5m=0` |
| 16–25 с | Ступени SPEC-004 доходят до отхода: переход к основанию лестницы **запрещён на 30 с и записан в память** как «трудное место» (`allies5m=0`: ждущие в очереди не считаются застрявшими союзниками) | `UNSTICK MEMORY record ... to=(2116.5,1879.7,90.2)` ×3 к 24,8 с |
| 31,65 с | Ботов пересоздают (вторая волна). Память уровня не сбрасывается | нет новой строки `UNSTICK MEMORY Shore:` |
| 31–65 с | Боты второй волны внутри корпуса **ни разу не берут лестницу**: путь с наценкой обходит её основание, бот кругами бегает по отсеку x 2110–2129 (это и есть «туда-сюда»), 1–2 разворота каждые 7 с | MOVE TRACE 130973: (2117→2129→2117→2110→…) |
| 65 с → конец | Бот падает в воду внутри корпуса (z 87,7), старт пути вне навмеша, дальше только fallback; датчик в воде заглушён | `NAV fallback ... reason=start_unprojected` 981 раз в боксе подлодки; 130993 — 91 с в 2,5 м, swim=1 |

Итог: ожидание в очереди у единственной лестницы считается застреванием, ступени выхода запрещают и запоминают единственный выход, и память делает это постоянным. Отдельно: внутренний затопленный отсек — тупик для навигации.

## Что делаем (под `wb_bot_sub_exit`; п. 0 — из раздела «Первым делом»)
0. **Край ямы:** см. «Первым делом», вариант 1.
1. **Очередь к лестнице.** Если следующий угол пути — начало связи-лестницы и лестница занята или у ворот уже ждёт ближайший, бот встаёт в слот очереди на линии подхода (2,5 / 4 / 5,5 м от основания, по порядку расстояния) и ждёт. В очереди датчик SPEC-004 заглушён так же, как у ворот (`ShouldYieldLadderStart` получает и стоящих в очереди), `UNSTICK spread` не считает стоящих в очереди помехой.
2. **Выход к связи не наказывается.** Переход, конечный угол которого — начало связи (лестница, прыжок) в пределах 3 м, не получает запрета отхода и не пишется в память (`UnstickShouldRecord` + проверка связи). Узкое место связи — не вина места.
3. **Старые записи.** Записи памяти в пределах 3 м от начала связи при чтении игнорируются (живые файлы Memory не подменяем и не переписываем, фильтр на чтении).
4. **Затопленный отсек.** Путь не прокладывается через воду внутри корпуса (вода ниже палубы в боксе подлодки); бот, оказавшийся в ней, ищет ближайшую точку навмеша (расширенная проекция до 3 м по высоте) у основания лестницы и плывёт к ней. Без SetPos и импульсов.
5. **Лог:** `SUB QUEUE bot= slot= ladder= ahead=`, `SUB WATER bot= pos= target=`.
