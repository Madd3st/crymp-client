## 1. Оценка проекта

### 1.1 Что хорошо

- **Граница с движком чистая.** Нет fake INetChannel, нет глобального `IsPlayer()`,
  нативное оружие/физика/костюм, `ShotValidator` принимает только реальный не-remote
  снаряд своего бота. Один-строковые guard'ы `Owns(id)` в Player/GameRules/ShotValidator.
  Риск upstream-merge низкий (`ARCHITECTURE_REVIEW.md` §«Done well»).
- **Разделение «намерение → исполнение».** `BotIntent` — значение; BotLocomotion/BotSuit/
  BotMovement исполняют через нативные механизмы. Нет телепорта, нет прямых записей HP.
- **Multi-bot готов структурно.** `BotManager` (реестр по EntityId) + `BotInstance` +
  `BotTargeting` (боты целятся в ботов) + `BotProfile` (6 стилей × 4 навыка).
  M3 (2 бота) и M4 (6 ботов) SERVER-LOG PASS (`STATUS.md` §M3/M4).
- **Настоящая автоматизация QA.** headless loopback-сервер, `wb_log_report.py`,
  Triage `summary.json`, demo-запись 20 Гц, unit-тесты, map-memory.
- **Документация дизайна сильная.** `POWER_STRUGGLE_DESIGN.md`, `MULTIBOT_DESIGN.md`,
  `ARCHITECTURE_REVIEW.md` — конкретны, с хэшами и ссылками на строки.

### 1.2 Что слабо

- **`warsbots/main` заморожен** на `caf1a815` (2026-10-23); вся работа на `weapon-goals`,
  ничто не смержено. Значение живёт на ветках, а не в игре владельца.
- **Навигация не доказана.** `BotNav` (сетка 3 м + A*, `ef376469`) написана, но **не собрана/
  не прогнана**. Нет jump-рёбер, cover-выбора, флангов. Доказан только локальный avoidance.
- **Бой без тактики.** Восприятие — всенаправленный LOS (нет FOV/слуха/стимула урона),
  память цели ~3 c, нет укрытий/флангов/высоты. Cover-поведение (`ef376469`) не собрано.
- **Не проверен бот против человека** на текущей ветке; два одновременных клиента — никогда;
  клиентская репликация N ботов — нет (`STATUS.md` L51-58).
- **Два незакрытых бага**: headshot −1067 (SP-таблица урона, `ARCHITECTURE_REVIEW.md` §«Headshot»)
  и spawn195 native revive defect (подтверждён, не исправлен, `STATUS.md` L307).

### 1.3 Выдержит ли архитектура PS

**Да, без переделки — при одном условии.** `POWER_STRUGGLE_DESIGN.md` уже задаёт правильную
границу `IBotGameMode` (IA-адаптер / PS-адаптер) и `PSCommander` (1 Гц, стратегия). Текущие
`BotBrain`/`BotCombat`/`BotNav`/`BotTargeting` переиспользуемы как есть. Два блока:

1. **`channelId=0` в PS** — команды/объективы/voice/revive-волны завязаны на канал
   (`PowerStruggle.lua` `reviveQueue[playerId]`, `QueueRevive`, `CommitRevivePurchases`;
   `GameRules::SetTeam` пишет `m_channelteams[channelId]`). Нужен аудит каждого RPC на
   разыменование канала — это работа, а не архитектурный тупик (`POWER_STRUGGLE_DESIGN.md`
   §«channelId=0»).
2. **Spawn groups** — `BotMatch::Register` сейчас явно отклоняет группы, а `BotInstance::Revive`
   берёт IA-спавн и team 0. PS требует групп/волн. Это расширение `IBotGameMode`, не переделка.

**Не откладывать**: IBotGameMode-заголовок нужен до того, как PS-логика начнёт прорастать
в BotBrain. Пока PS — только доки и экспорт геометрии, переделывать нечего.

| Область | Оценка | Обоснование |

| Тестируемость | **7** | Реальный headless QA + Triage + demo + unit. Минус: шумные gate, нет автотеста клиентской репликации |

### 1.5 Топ-5 рисков

1. **Release starvation** — main заморожен, 40+ коммитов на ветках, merge-ад и «готово ≠ в игре».
2. **spawn195 native revive defect** — воспроизводится стабильно (~5 c), три серии экспериментов
   не закрыли; блокирует gate «no stall».
3. **Нет bot-vs-human и клиентской репликации N ботов** — главная ценность (боты против людей)
   не подтверждена на текущей ветке.
4. **Процесс дороже результата** — лимиты горят на сборки/QA/вердикты, фичи ползут медленно.
5. **`channelId=0` в PS** — команды/объективы/покупки завязаны на канал; без аудита PS не взлетит
   (плюс headshot-паритет −1067 как под-риск честности боя).

## 4. Технические решения под CryEngine 2

### 4.1 Навигация в MP

**Решение: собственный grid-граф + A* (`BotNav`), НЕ Recast, НЕ CryAI.**
- CryAI: на IA-картах нет навигационных данных (пустые `*.bai`), а путь Co-op требует
  `gEnv->bMultiplayer=false` + `pAISystem->Init()` — запрещено (`ARCHITECTURE.md` решение 7).
- Recast/Detour: лицензионно OK (Zlib), но главная цена — извлечение геометрии + off-mesh
  связи + offline-bake. Оценка 6–9 недель. Отложить до доказанного спайка.
- `BotNav` (сетка 3 м, ≤5 этажей, ray-verified рёбра, A*) уже написан. Дожать: jump/strength
  рёбра (свойство ребра, проверка в `BotLocomotion::JumpSpace`), cover-узлы. Позже heightmap
  для открытых участков, если сетка не покроет.

### 4.2 Логика решений

**Решение: FSM (текущий BotBrain) + приоритетный арбитр целей. НЕ BT/GOAP/HTN.**
- BT/GOAP/HTN — тяжёлый фреймворк, плохо ложится на «код пишут агенты» и на ручные
  приёмочные проверки. GOAP в Omni-bot — заглушка (`EXTERNAL_AI_RESEARCH.md` §3.4).
- Utility — только для *выбора цели* (`EngagementScore`), не для всего поведения.
- Арбитр: `BotGoal {priority, canInterrupt, resume}` по образцу YaPB `TaskStack`. Дешёво,
  решает текущую слабость (при появлении врага патруль теряется без возврата).

### 4.3 Сервер vs клиент, производительность, сеть

- **Сервер авторитетен.** Путь/узлы не реплицируются; клиентам — только поза/спринт/прыжок/
  костюм через `BeginOptionalGroup`. Правило R12 уже соблюдено.
- **Бюджет восприятия.** Сейчас O(N²) сканы целей + FindNearby по всем entity. При N>8 —
  time-slice + кэш видимости + `GetEntitiesInBox`. Измерено: 6 ботов ≈0.077 ms/frame,
  15 ботов ≈0.31 ms/frame, худший кадр 1.37–17.8 ms (старый entity-итератор). После замены
  FindNearby — перезамерить.
- **Клиент не создаёт физику.** Клиент проигрывает анимацию по `jumpSerial`; сервер — источник.

### 4.4 Грабли CryEngine 2 и обход

| Грабли | Обход |
|---|---|
| `IsPlayer()` невиртуален, зависит от channelId | держать EntityId в реестре, не менять глобальный IsPlayer |
| `channelId=0` → нет input/канала; `ServerSynchedStorage` разыменовывает null channel | не вызывать `OnClientConnect(0)`; scoped-хуки в Player; не подделывать канал |
| `SerializeSpawnInfo` вызывается ДО `Init` | в early-этапе только сохранять marker, не трогать GameObject/GetChannelId/костюм |
| `Base` аллоцирует CGame → define должен идти PUBLIC во все потребители | иначе map-load crash в CryAction offset0x2db517 |
| `version.h` = git describe → пересборка CryGame на каждый коммит | не менять version.h на doc-коммитах |
| CRLF ломает manifests; кириллический путь требует RC `/c65001`; OneDrive лочит EXE | LF-тулинг, `/c65001`, чек-аут вне OneDrive (`WarsBotsBuild`) |
| file-only канал лога режет telemetry ниже -verbosity | отдельный `<log>.bots.log` (`BotLog`) |
| Оба EXE (клиент+сервер) должны быть одной experimental сборки | никогда не смешивать версии; optional-группы сохранять |
