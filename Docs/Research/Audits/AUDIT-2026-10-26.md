### Рабочий цикл одной задачи (от постановки до вливания в main) + Definition of Done

1. **Постановка** (Claude, `C-xxx`): что, зачем, acceptance-метрика, какой cvar/пресет, exit-критерий флага
   (promote/diagnostic/delete). Один пункт = одна тема.
2. **ACK** (Codex, ≤10 мин) → **STARTED + ETA**.
3. **Офлайн-проверка** (Claude/DeepSeek, секунды–минуты): unit-тесты + `compile_check.sh` + `walk_sim` на геометрии.
   Провал — возврат на (1), прогона нет.
4. **Build** (Codex): MSVC x64 client+server + тесты; тривиальные ошибки — фикс на ветке и отчёт.
5. **Probe** (Codex, 1–3 мин): stair/duel/duel_30m по сценарию. Провал — стоп.
6. **15-бот pair** (Codex, acceptance, 2 seed × 330–660 с) — только для acceptance/поведения.
7. **Verdict** (Claude): `summary`/`pace`/`demo`/`look_walls` в шуме или нет; фиксируется в X-отчёте.
8. **Merge green → weapon-goals → main**, обновить `STATUS.md` + journal + одну строку в outbox.

**DoD (Definition of Done)** одной задачи: (а) acceptance-метрика PASS по схеме `REPORT_SCHEMA.md`;
(б) `summary.json`/demo-метрики в репо или по ссылке; (в) exit-критерий флага записан в C-пункте;
(г) `STATUS.md`/journal обновлён; (д) outbox-строка `DONE <sha>`. Всё посильно одному агенту за один цикл.

## 2. Архитектура под Power Struggle

### 2.1 Границы режима игры: `IBotGameMode` отсутствует

Абстракции режима нет. Режим проверяется строковым сравнением класса GameRules, захардкоженным в 4+ местах:

- `BotMatch.cpp:14` `strcmp(...,"InstantAction")` в `IsBot`
- `BotMatch.cpp:23` — в `Collect`
- `BotMatch.cpp:76` — в `Unregister`
- `BotManager.cpp:510` — в `WatchCommand` (`const bool ia = ... "InstantAction"`)

Плюс ворота: `BotManager::CanRunLocalIA()` (`BotManager.cpp:230`) пускает AI **только на IA**;
`CanRunLocalExport()` (`BotManager.cpp:235`, `CryMPEngineAdapter::LocalExportGate`, `813c43c1`) отдельно
разрешён для PS, но только как **read-only экспорт геометрии**, без ботов.

Вывод: при первом PS-фиче придётся либо заводить `IBotGameMode` (рекомендуется), либо размножать `strcmp` ещё
сильнее. Сейчас это самый крупный незакрытый фундамент.

### 2.2 `channelId=0` как маркер бота — все места

Бот идентифицируется по `GetChannelId()==0` / `IsPlayer()==false`:

| Файл:строка | Назначение |
| --- | --- |
| `BotInstance.cpp:288` | revive guard отказывается при `GetChannelId()!=0` |
| `BotInstance.cpp:371` | очистка/CanRunLocalIA требует `GetChannelId()==0` |
| `BotManager.cpp:196` | `human = GetChannelId()>0 && GetNetChannel(...)` (исключает ботов) |
| `BotManager.cpp:753` / `:759` | фильтр кандидата-наблюдателя / исключение ботов |
| `BotMatch.cpp:54` | лог регистрации `channelId=0 nativeIsPlayer=0` |
| `BotMoveTrace.cpp:26` | трассировка `if (bot || GetChannelId()>0)` |
| `BotDemoRecorder.cpp:81` | `if (!bot && !actor->GetChannelId()) return nullptr` |

Это работает только пока бот — единственный канальный-0 актёр и `IsPlayer=false`. PS не меняет этот факт сам
по себе (бот останется канальным-0), но **всё, что в PS завязано на канал/команду/список `GetPlayers`, бота не
увидит** (см. 2.3).

### 2.3 Регистрация участника — только InstantAction

`BotMatch::Register` (`BotMatch.cpp:27-56`):
- читает `USE_SPAWN_GROUPS` (если true — отказ: «spawn-group channel callbacks unsupported»),
- грузит `Scripts/WarsBots/InstantAction.lua`, вызывает `WarsBotsIA:Attach(rules)`,
- `ResetScore(ScriptHandle(id))`, `SetSynchedEntityValue(id, SCORE_*_KEY)` — имена ключей счёта `SCORE_KILLS_KEY/
  DEATHS_KEY/HEADSHOTS_KEY/PING_KEY` захардкожены для IA (`BotMatch.cpp:76-87`),
- **`SetTeam` нет вообще** (IA — FFA, команды не нужны).

Спавн тоже без команды: `ChooseSpawnLocation` (`BotManager.cpp:245`) перебирает единый `GetSpawnLocationCount()`;
`rules->GetTeam(id)` вызывается только в revive-пути (`BotManager.cpp:780`).

### 2.4 Что сломается первым, когда придут команды/захват/закупка/техника

По порядку появления:

1. **Регистрация и команда.** Нет `SetTeam`, нет PS-attach-скрипта, ключи счёта IA-специфичны. Бот не станет
   полноценным участником PS, пока не будет team assignment + PS-вариант регистрации.
2. **Спавн.** PS спавнит по командам/группам (`USE_SPAWN_GROUPS`), не единым списком — `ChooseSpawnLocation`
   выберет точку чужой команды.
3. **Закупка/экономика.** `EquipLikePlayer` (`BotMatch.cpp:58`) вызывает IA `EquipPlayer`; действия «потратить
   prestige» на оружие/технику нет нигде.
4. **Захват точек.** Нет цели «захватить» и осведомлённости о capture areas (данные уже есть в
   `DeepSeek/PS_RULES.md`, `PS_MAPS.md`, `ps_shore.json`/`ps_plantation.json` — но не код).
5. **Техника.** Нет vehicle executor/входа в машину.

1. **Приоритет PS против доводки IA.** Вкладываем ли мы сейчас в «бой дальше 40 м / сложности / прицел» (E1–E3),
   или сразу идём в T-0 `IBotGameMode` + PS-прототип (E6–E8)? От ответа зависит, что выкидываем: доводка IA или
   отсрочка PS.

   команды всегда)? Нужно, чтобы спроектировать T-0 team model без переделки.

   SCAR, или сразу техника и commander-orders? Это режет E8 пополам.

   probes и offline), даже если это замедлит приёмку поведения? Это задаёт темп всего плана.
