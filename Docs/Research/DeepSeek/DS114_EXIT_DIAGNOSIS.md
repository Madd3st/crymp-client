# DS114 (v3) — C154 native top exit: bounded graph preparation for the owned ladder

Status: offline design + oracle specification for Codex. No engine/QA/game/data/install/launcher/restore writes by
DeepSeek. v3 supersedes v2; the v2 physical-stance candidate is **withdrawn** (see 1.3).

## 1. Corrections carried into v3

1.1 **Enum (v1 error, withdrawn).** `motionFlags=796` = `0x31C` is `EAnimatedCharacterFlags`
(`Code/CryCommon/CryAction/IAnimatedCharacter.h:56-83`: `PerAnimGraph 0x4 | ZCoordinateFromPhysics 0x8 |
EnableMovementProcessing 0x10 | ImmediateStance 0x100 | UseHumanBlending 0x200`), not
`CAnimation::m_AnimParams.m_nFlags`; it proves nothing about `CA_MANUAL_UPDATE` or the ladder FIFO.

1.2 **Exit trigger (v1 error, withdrawn).** `UpdateLadderAnimation(eLS_ExitTop)` sets `Signal=exit_ladder_top`
(`Player.cpp:7449`) and `Action=idle` (`:7453`) and returns false; `LeaveLadder` ignores the return (`:7335`).
The exit is Signal/state driven, not FIFO driven. An empty `OnLadder` means "no current state defines this output"
(`IAnimationGraph.h:497-499`), not "the graph never left the ladder".

1.3 **Physical stance fix (v2 candidate) is unsafe and withdrawn.** `player.lua` (GameData.pak, derived actor)
overrides the stance table with five rows and leaves two rows as `stanceId = -2` "ignored by CActor::SetupStance"
(lines 90-93 and 149-152), i.e. `STANCE_STEALTH` and `STANCE_RELAXED` are not configured for Player;
`CActor::SetupStance` refuses them (`stance >= STANCE_NULL` = -1, `Actor.cpp:1277-1281`, enum `IAgent.h:381-393`).
Forcing `STANCE_RELAXED` would therefore use an unconfigured stance (zero/invalid speeds, capsule risk) and the
controller divides by that stance speed (`PlayerMovementController.cpp:847,856`). Player's configured STAND is
`name="combat", normalSpeed=1.75, maxSpeed=4.5` (`player.lua:79-87`).

1.4 **Geometry datums.** Native ladder-entity AABB top `100.291` and nav ladder-link endpoint `99.768` are different
datums; the exit-frozen feet `97.927` is 2.364 m below the native AABB top and 1.841 m below the nav endpoint.
Completion must never be granted at that position.

## 4. Bounded candidate: prepare the animation graph, never the actor

Scope: `WarsBotLadderServer(player)` only (server + `IsWarsBotActor` + `wb_bot_ladder==1` + BotManager ownership),
while the native ladder is attached. Everything else is untouched.

4.1 Snapshot on attach (owned ladder only): validate `InputID stanceId = pAGState->GetInputId("Stance")` with
`GetInputName(stanceId)` (must be non-null / `"Stance"`), read the current value with `GetInput(stanceId, char[256])`
and `IsDefaultInputValue(stanceId)`, and read `GetAnimationActivation()`.

4.2 Prepare: set the **animation** `Stance` input to `"relaxed"` (idempotent, re-applied while attached because the AC
may push its own stance), and only if `GetAnimationActivation()` is false call `SetAnimationActivation(true)` for this
route. No `Update()` call, no double tick. The actor keeps physical STAND, requested base speed
`GetStanceMaxSpeed(STANCE_STAND)` = 4.5, same capsule, same climb speed (controller ratio stays 1.0 because the
physical stance does not change).

4.3 Restore exactly on: native leave (`isOnLadder` false), policy Done/Failed/Cancel, death/ragdoll/frozen,
`wb_bot_ladder != 1`/OFF, bot stop/removal, level end. Restoration uses the snapshot: `ClearInput(stanceId)` when the
old value was the default, otherwise `SetInput(stanceId, previous)`; `SetAnimationActivation(previous)` only if this
route changed it. Exactly once, idempotent, and never for non-owned actors.

4.4 Exit stays stock: trigger, axis, speed and the strict physical guard `NativeLadderExitPhysicalReady`
(`BotLadder.h:18-29`, near the top **and** laterally out of the shaft) are unchanged. If the off-top state now runs,
its root motion supplies the lateral egress. Completion rules:
- `OnLadder == '0'` -> existing stock path with the physical veto (unchanged);
- `OnLadder` empty/default after the state ends -> treat as native completion **only** if
  `NativeLadderExitPhysicalReady(feet, bottom, top)` is true (real egress near the native top);
  never at `97.927` inside the shaft, never on height alone;
- otherwise keep waiting and let the policy fail closed (`blocked_top`), as today.

4.5 Telemetry in the existing `WB_LOG(2)` lines (no new cvars/flags): state name, activation before/after, Stance
input before/after, Item input (read-only), plus the existing output/motionFlags/pos. Enough to decide the remaining
unknowns in one run.

## 5. Evaluation of the proposal (supported vs assumption)

Supported by code/assets: the interface calls exist (`IAnimationGraph.h:365-368` string `SetInput`,
`:418 ClearInput`, `:422 GetInput(char*)`, `:425 IsDefaultInputValue`, `:428 GetInputName`, `:468 GetInputId`,
`:474-475` activation get/set); the XML selectors need `Stance=relaxed`; the physical stance fix is unsafe
(1.3); the system-level `IAnimationGraphSystem::SetAnimationGraphActivation(EntityId,bool)` is an **empty stub**
in this rebuild (`Code/CryAction/AnimationGraphSystem.cpp:65-67`) and cannot be used.
Assumptions that only the run can settle: that `SetInput("Stance")` is not overwritten by the AC every frame
(mitigated by re-applying while attached and logging before/after); that the graph is ticking at all (activation may
already be true); that the off-top animation's root motion actually moves the owned actor; that the graph `Item`
input is `nw`. No forced `Update()`, no manual `ReachedEnd`, no SetPos/impulse/timer, no capsule or stance change.

## 6. Real-caller oracle (engine-free, extracted actual code; RED 272 / GREEN candidate)

Extend the DS112/DS108 pattern (extract the real ladder adapter/helper and the exit block, mock the graph state):
- attach (owned): `GetInputName` validated, snapshot read once, `SetInput("relaxed")` applied (and re-applied while
  attached), activation enabled only when it was false, **zero** `Update()` calls;
- untouched: no `CActor::SetStance`, no `GetStanceMaxSpeed(STANCE_RELAXED)`, no capsule change; base speed still STAND;
- scope: human/`wb_bot_ladder=0`/non-server/non-owner/client/dead/frozen/ragdoll -> zero graph writes;
- restore: previous value (`ClearInput` when default) and previous activation restored exactly once on each
  termination path;
- completion: empty + physical egress true -> complete; empty + `97.927`-style position -> wait/fail; `'1'` -> wait;
  `'0'` -> stock path with physical veto; no manual `ReachedEnd` elsewhere;
- no `SetPos`/impulse/timer/manifest-bypass in the extracted block; DS112 climb-caller and DS108 motion-mode stay green.
