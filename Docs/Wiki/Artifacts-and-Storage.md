## Что содержит доказательство

Нужны точный код SHA, полный зелёный CI, пара EXE с совпадающими хешами, версия данных/сценария, свежее ревью, итог выполнения и честные ограничения. Для игрового результата сохраняются логи и демо с полным хвостом и build-prefix, затем проверяется восстановление исходных данных. Неудачные попытки сохраняются и объясняются; их нельзя стирать ради красивого статуса.

Текущие C154 архивы `build/c154-route-*`, V5 данные, actualmanifestreceipt и видео владельца ещё нужны — это не мусор. Большие бинарники/геометрию/демо не коммитим в Git; там остаются отчёты, рецепты и индексы.

## Что очищено 29.10 и как вернуть

Старые C019rawOBJ перенесены в `E:/WarsBots/Archive/2026-10-29/C019-geometry`: каждый ZIP проверен по распакованному SHA256 и имеет манифест исходного пути. Сжатые crop и sidecar на C сохранены. Текущая геометрия Shore не затронута.

Старые временные review-worktree находятся в архиве `…/Git-worktrees`: exactHEAD/ref, Git-bundle, staged/unstagedbinarypatches, status; для грязных checkout — полный ZIP с хешем каждого файла, включая untracked/ignored. `.git`pointer в ZIP не переносится. Восстановление: проверить bundle, добавить новый detachedworktree на сохранённом ref, применить stagedpatch с--index и unstagedpatch, извлечь ZIP поверх него, сверить манифест. Не распаковывать поверх действующего checkout.

Старые производные EXE/PDB/ILK из закрытых QA-задач сохранены в `…/CI-binaries`; исходные пути/хеши и ZIP указаны в manifest.json. Их копии на C удаляются только после проверки сохранённых байтов. Восстановить нужный файл можно по относительному пути из ZIP.

## Правила, чтобы снова не накопить свалку

- Новые большие пакеты и архивы размещаем на E. На C — текущие небольшие исходники/инструменты, необходимые работающие данные и активные доказательства.
- Перед удалением проверяем абсолютную границу каталога, отсутствие reparse/nestedrepo, неизменность HEAD/status/байтов и архив. Никаких широких gitclean-fdx, удаления истории или чужих незакоммиченных изменений без сохранения.
- Историческую переписку переносим в датированный архив. В активном ящике — только текущие задачи и свежие результаты, в текущем состоянии — один связный снимок, без десятков старых NOW.
- Не удаляем видео владельца, установленные игры, живые базы и историю приложений как «кэшсборки». Активные Code/SDK, лицензии, навигацию, Memory и восстановление сохраняем.
- Сессия агента перезапускается при 50%контекста или ежедневно после push/idle; wake переключается на новую сессию. Архивирование переписки в Git не означает ручное удаление внутренних баз Codex/OpenCode.
