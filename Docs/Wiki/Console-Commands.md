# Команды и настройки

Справочник относится к срезу **b8b444d6**. Полная регистрация: [BotManager.cpp](https://github.com/Madd3st/crymp-client/blob/b8b444d6c858f27a1fdde0d93b25a318cafc6937/Code/CryGame/Bots/BotManager.cpp) и [BotConfig.cpp](https://github.com/Madd3st/crymp-client/blob/b8b444d6c858f27a1fdde0d93b25a318cafc6937/Code/CryGame/Bots/BotConfig.cpp); значения полей — `BotConfig.h`. Точный готовый рецепт содержится в `preset.json` пакета. Не включай «все фичи» по старому примеру.

## Сервер: боты

| Команда | Назначение |
| --- | --- |
| `wb_add 8 normal` | Добавить восемь ботов Normal при открытых локальных gates |
| `wb_add 1 elite` | Добавить одного Elite |
| `wb_list`, `wb_status` | Список и состояние; использовать для диагностики фактического состава |
| `wb_remove N` | Удалить бота с номером N |
| `wb_remove_all` | Удалить всех ботов текущего менеджера |
| `wb_skill 1` | Значение CVar навыка по умолчанию для последующего `wb_add`: 0 beginner, 1 normal, 2 veteran, 3 elite |
| `wb_debug 1` | Команда включения подробной отладки; не трактовать как зарегистрированный CVar |

Серверные команды выполняются в серверной консоли/рецепте, клиентские — в клиенте. В Power Struggle удаление может завершаться асинхронно; `wb_remove` не означает, что актёр уже исчез в тот же момент.

## Клиент: просмотр и отметки

| Команда / клавиша | Где действует |
| --- | --- |
| `wb_watch list`, `wb_watch next`, `wb_watch prev`, `wb_watch off` | **Только Instant Action и штатный spectator**; не Power Struggle |
| F6/F7 | В профиле Steelmill: следующий/предыдущий бот |
| F1 | Штатное переключение вида наблюдателя |
| F8 | В профилях C150: отметка для последующего разбора |
| `r_displayInfo 1` / `0` | Диагностический оверлей / скрыть |
| `wb_bot_client_smooth 1` | Клиентское сглаживание реплик ботов |

## Рецепт и диагностика

`wb_probe_local_test=1`, loopback bind и LAN-only открывают явный локальный opt-in. Навмеш включается через `wb_bot_navmesh`; особые переходы — `wb_bot_jump_links` и соответствующие файлы карты. `wb_log` и `wb_move_trace` управляют наблюдаемостью и должны соответствовать конкретному рецепту.

Переключатели PS, дверей, покупки и техники проверяй в актуальном коде и отчёте; наличие имени не означает принятую фичу. `wb_bot_corners` и `wb_bot_jump_sanity` были включены решением D016; старая формулировка «все флаги спринта OFF» неверна. Для новых defaults требуется отдельное решение.

Диагностические `wb_teleport` / `wb_revive_at` меняют эксперимент: их нельзя выдавать за естественный выход с базы. `wb_geom_export` и `wb_nav_*` используются инженерными рецептами; конкретные аргументы брать из исходника и связанной задачи.

## Изменения разработки C154

Эти команды относятся к исходнику **`3cfd8596`**, это историческая точка введения команд, а не текущий кандидат. Текущий C154 —307; замороженные C150 остаются на b8, C155 —abac. [Регистрация нового среза](https://github.com/Madd3st/crymp-client/blob/3cfd859676d83bdecc1b091d3b9202323b039135/Code/CryGame/Bots/BotManager.cpp).

| Команда | Контракт |
| --- | --- |
| `wb_bot_ladder 1` | Разрешает UP-связи типа ladder и штатный исполнитель лестницы; default0. Нужны соответствующие данные карты и открытые gates, физическая приёмка обязательна |
| `wb_nav_audit` / `wb_nav_audit 0` | Офлайн-подобная диагностика навмеша в локальном сервере без актёров, базовый вариант |
| `wb_nav_audit 1` / `2` | Сохранённые диагностические варианты прежнего `wb_nav_knee_fix`; отдельный CVar удалён |
| `wb_nav_audit stop` | Остановить/сбросить диагностику |
| `wb_revive_at 545 2` | Одна явно назначенная штатная точка возрождения для бота №2; native kill/revive, не случайный спавн. В C154 используется только как раскрытая начальная постановка опыта |

После постановки маршрута новые возрождения, переносы или спасения не могут засчитываться как успешное прохождение.
