Ты — внешний ревьюер-архитектор игрового ИИ. Проведи независимый аудит проекта WarsBots: боты для Crysis Wars на
движке CryMP (открытый клиент/сервер CryEngine 2, C++). Мне нужна критика и конкретные правки, а не пересказ.

## Контекст (кратко)

- Цель: боты, которые играют в Instant Action (deathmatch) как люди на всех IA-картах (Steelmill, Quarry, Armada,
  Outpost), позже Power Struggle. Важны вертикальный геймплей (прыжки, прыжок силы на 4.7 м), нанокостюм (броня /
  скорость / сила / невидимость), выбор оружия (SCAR лучший), стабильные решения и человеческий прицел.
- Ограничения: боты — серверные сущности `CPlayer` без сетевого канала; только локальный LAN-сервер (127.0.0.1);
  нельзя трогать античит, подделывать каналы и патчить бинарники движка; родной CryAI на MP-картах не работает
  (в картах нет AI-навигации). Сервер не умеет крутиться быстрее реального времени.
- Команда: владелец (играет, решает), Codex (весь игровой код, сборки, прогоны), Claude (координация, офлайн-анализ
  логов — инструмент Triage), OpenCode (исследование кода только на чтение и ревью). Общение агентов идёт через
  markdown-ящики в git.
- Где мы сейчас: (1) навигация — самодельный граф по лучам (7.6k узлов) оказался тупиком: 25 % узлов — ловушки,
  нет лестниц, перил, уступов, 90 % ошибок маршрута — «нет пути». Решили перейти на Recast/Detour по геометрии
  карт (геометрия 4 карт уже выгружена, офлайн-модель с прыжковыми связями есть). (2) Скорость ботов доведена до
  человеческой (медиана 4.5 м/с против 5.8 у владельца, спринт пока 22 % против 55 %). (3) Мозги — конечный автомат
  в одной функции на 361 строку, решения дёргаются между «бегу к оружию» и «гонюсь за врагом», прицел «гуляет».
  (4) Дальше по плану: внутриигровые демки (запись поз и взгляда 20 Гц + «дорожка мозгов» бота + проигрывание через
  режим зрителя), обязательный рефакторинг, приоритет оружия, фикс прицела, переход на навмеш, потом ML (подбор
  параметров → обучение решений по демкам → подражание владельцу).

## Что нужно от тебя

1. **Архитектура бота.** Оцени целевую архитектуру слоями: восприятие → память → решения → тактика → движение и
   прицел → исполнение. Чего не хватает, что спроектировано неверно, в каком порядке строить. Конкретно:
   конечный автомат против utility AI / behaviour tree / GOAP для этой игры; модель восприятия (поле зрения,
   невидимость, звук); модель прицела (человекоподобные рывки и сопровождение, отдача, ошибка по уровню навыка);
   использование костюма как тактика.
2. **Навигация.** Верно ли решение Recast/Detour + авто-прыжковые связи + прыжки из трасс владельца? Альтернативы,
   риски, как проверять, нужны ли динамические препятствия и тайлинг, как исполнять прыжковые связи.
3. **Процесс и качество.** Где мы снова рискуем лечить симптомы? Метрики и проверки: парные прогоны, `summary`,
   метрики по демкам. Чего не хватает (регрессионный набор, рейтинг ботов между версиями, проверки на нескольких
   картах, метрики «человечности»).
4. **Роадмап.** Оцени очередь из STATUS.md («Queue»): что убрать, что переставить, что добавить. Учитывай, что
   Codex — узкое место с недельным лимитом, а Claude и OpenCode не пишут игровой код.
5. **ML.** Реалистичен ли план (подбор параметров → обучение решений по демкам → подражание владельцу) без
   ускорения времени симуляции? Что записывать в демки уже сейчас, чтобы потом не переделывать формат?
6. **Топ-10 рисков** с вероятностью, ущербом и способом снизить.

## Формат ответа

- Короткое резюме: 5–7 пунктов, самое важное первым.
- Разделы по пунктам 1–6. В каждом: проблема → почему это важно → конкретное предложение (где возможно — ссылка
  на файл и строки) → как проверить, что стало лучше.
- В конце **предлагаемый роадмап** таблицей: шаг, исполнитель (Codex / Claude / OpenCode / владелец), критерий
  готовности, оценка в днях. Плюс отдельный список «перестать делать».
- Если с чем-то из наших решений не согласен — скажи прямо и объясни. Не придумывай факты о коде: что не видел,
  помечай «не проверено».
