## Confirmed server defect and scoped correction

User explicitly authorized stopping the old server. Verified PID150204/old log/EXE,
then stopped only that process and archived final logs in
`build/p0-duel-01/old-session/`. No graphical client was launched or controlled.

Diagnostic pilot on frozen `2fcb4c0f` found pairs of shot callbacks at the same time,
with a second ammunition decrement. Source review confirmed CSingle::Shoot already
creates its authoritative projectile, decrements ammo and sets the native next-shot
timer; CWeapon::RequestShoot then broadcast ClShoot AND called local NetShoot/Ex on
that dedicated server. NetShoot makes a remote replica, decrements ammo again and
sets m_next_shot=0. That reset can defeat automatic native fire-rate timing.
Do not interpret this as proof both projectiles caused damage: existing validator
rejects remote bot-projectile hits. Human rapid-death attribution remains unresolved.

`WeaponClientServer.cpp` now retains client broadcast but skips the redundant local
NetShoot/Ex only for server-owned registry actors with channelId0. Real players,
non-owned actors, protocol/RMI signatures and ShotValidator remain unchanged. No
fake channel or global IsPlayer change. This is a scoped authoritative-shot fix,
not a PS networking feature. Real-client replication still needs visual regression.

## Telemetry and validation boundaries

Actual OnShoot records distinguish authoritative vs remote vs unknown replica state.
The existing wb_tactics_report.py now computes active native-shot intervals and clip
decrements only for remote=0. Active windows exclude gaps above max(1 s, 3 native
shot periods); alignment/reload/movement can still lengthen those intervals.
Unknown older callbacks are not silently treated as authoritative shots.

TTK excludes hits marked spawn-invulnerable; effective HP loss is clamped per impact,
Armor energy spent is separate, and material/head/part, distance, initial HP/energy
and contributors remain recorded. Observed targeted-fire-to-death includes misses
and possibly protected firing; first-impact-to-death has a different origin. Neither
metric invents a complete history if capture started late. Revive clears both hit
and shot-only context. Native HP rises were observed between some impacts (e.g.
16 ->19 before next hit); summed per-impact loss may exceed initial HP and must not
be mistaken for overkill. No health-regeneration change was made.
